# Monthly report implementation — draft

The first implementation delivers local manual generation, immutable monthly history, a Reports UI, authenticated viewing/download and existing jobs/audit integration. It does not activate any external AI, Pushover, scheduler or deployment.

## Operational contract

- Requires existing enforced authentication. No credential or auth configuration is created or changed. Readers can GET the report API; operators generate reports and use the existing operator-only UI session. Session mutations retain existing CSRF checks.
- `/reports` lists every saved version sorted by month/version with pagination. `/reports/:id` shows frozen facts, warning, PDF preview and download. Regenerate produces a new saved version and leaves old URLs intact.
- `POST /api/v1/reports` accepts `month`, explicit ISO `currency`, UUID `requestKey`, optional `supersedesId`. It waits for bounded local generation and returns 201 with the saved report. This intentionally simplifies the earlier 202/polling proposal; work still has a job/audit lifecycle. There are at most four pending requests and one generation at a time. Stop/drain supports shutdown.
- A successful request key replays its saved result; conflicting input returns 409. Failed/interrupted generation may be retried with the same key because it did not publish a report. This is not a durable distributed queue. One application writer is the supported homelab topology; unique database constraints prevent duplicate version assignment if deployment configuration is wrong.
- GET collection accepts limit 1–100 and offset, GET detail/PDF checks configured-budget ownership every time, with private/no-store responses and no public share routes.
- Existing SQLite stores metadata/facts; `${DATA_DIR}/reports` stores PDFs. Files are mode 0600 in a 0700 directory, fsynced then renamed before metadata is saved. Hash validation detects missing/corrupt downloads. Startup fails interrupted report jobs and removes only unreferenced UUID report/temp files older than 24h. Existing ready reports and job retention are independent. No backup infrastructure or backup/restore prerequisite is added; the user has declined that overhead.
- Arithmetic uses integer minor units and date-only calendar boundaries. Explicit currency must be supported and use two decimal places; no currency conversion. On-budget scope includes closed accounts. Hidden categories retain classification. Grouped Actual splits are validated and counted once. Refunds reduce category spending. Transfers are excluded; unmatched/perimeter transfers warn. Uncategorized inflows do not silently become income.
- The cache is read in one Actual queue operation without syncing. Captured output strips notes/payees via a schema. Latest record dates are evidence only, never import completeness. All coverage remains unconfirmed and prior-month comparisons are omitted.
- Summary is deterministic/local. Existing OpenAI/Gemini logging no longer includes prompt contents, streamed text, full responses or provider errors. Report generation does not invoke these adapters. A disabled-by-default notification adapter has a mock-tested generic payload and exact authenticated report link, but no Pushover HTTP transport or credentials are wired in this core draft; no credentials, external calls, notification or schedule activation exist. External narrative and generic notifications remain separate reviewed follow-ups.

## Dependencies and rendering

PDFKit 0.17.2 (MIT) is pinned; its types 0.17.3 are development-only. It keeps rendering in-process without Chromium or a new service. Local DejaVu Sans is bundled with its redistribution license and copied into the production image. Approximate installed sizes: PDFKit 5.9 MiB, fontkit 5.7 MiB, bundled font/license 752 KiB; these are disk sizes, not measured image delta. Renderer is one injected function and can be replaced without touching calculations or storage. npm production audit reported zero vulnerabilities during implementation. Deprecation warnings for transitive crypto-js and jpeg-exif remain dependency-review considerations; no remote assets are fetched. The rendered synthetic two-page sample was 17 KiB. Arbitrary script coverage beyond the bundled font, tagged-PDF accessibility, container image size and runtime benchmarks remain review items.

The initial PDF follows the design's typography, teal money cards, income allocation bar, category chart and prominent coverage language. Negative category totals are explicitly labelled net refunds. Long category/account lists paginate. Version metadata currently includes facts schemaVersion and renderer version below; changing presentation requires a new report generation, never rewriting saved bytes.

## Independent reliability review

Follow-up review adds checked intermediate minor-unit sums (so later refunds cannot mask an overflow), prevents timed-out/canceled generation from publishing, and scales large money values to fit PDF cards. Docker builder now matches the Node 24 distroless runtime to avoid native SQLite ABI mismatch. Regression fixtures additionally cover cross-budget file retention, cross-month regeneration rejection, and storage/metadata failure without partial publication. No additional backup system or deployment recovery machinery is introduced.

Validation after this review: 99 tests across 18 suites passed; lint and server/Vite build passed. A read-only distroless Node 24.14.0 container, with networking disabled and a temporary synthetic database, passed native SQLite loading, migrations, local font/PDF rendering, report generation, unauthenticated 401, authenticated PDF download, and history reopen. This smoke test mounted locally compiled output and dependencies; it did not build or start the live app. A single local 10,000-row synthetic sample measured 25 ms calculation and 100 ms PDF rendering (16,326 bytes); this excludes Actual capture and is not a production SLA.

Full Docker image build remains blocked by environment DNS resolution of deb.debian.org during apt-get, including a host-network attempt. No image was published. The existing 111 UI type errors also remain a release gate. Draft PR creation remains denied pending explicit user approval; it was not retried during this review. No backup/restore task is required by this feature milestone.
